# Goal 6 Working Loop

1. Read `goal-6/0-plan.md`, the completed Goal 2 transaction-function and Goal
   5 query boundaries, and actual source/tests; reconcile status with behavior.
2. Take the first unfinished stage and implement the smallest executable
   behavior that advances its completion signal.
3. Read the matching transaction/query function documentation and trace the
   narrow `1.0.7705` function, extensions, expansion, or expression path before
   deciding timing, authority, representation, or error behavior.
4. Keep persisted execution inside the explicit deterministic ABI and charge
   every instruction/read/output to request limits. Generated data always
   returns through existing validators.
5. Use pure differential tests for interpreter semantics and real PostgreSQL
   for deployment, activation, retry, corruption, concurrency, and restart.
6. Record only material runtime decisions, threat boundaries, recovered
   mappings, significant deviations, measurements, and truthful stage status.
7. Continue through the exit condition; a bytecode enum, one demo function, or
   a deployment table is not controlled programmability by itself.
8. If blocked, record the exact authority or semantic gap and the next
   state-changing test/implementation rather than advancing Goal 0.

Prefer a small auditable shipped runtime over runtime-framework ceremony. Do
not implement Goal 7 leadership/services or Goal 8 operations here.
